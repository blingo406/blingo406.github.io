# Mizuki 博客管理器

双击仓库根目录的 `Blog-Manager.cmd`，或在仓库目录运行 `pnpm blog:manager`，打开 http://127.0.0.1:4399/。

默认读取 `C:\Users\22596\Documents\Mizuki Blog`，递归扫描 Markdown、MDX 和 TXT。隐藏目录（例如 `.obsidian`）会跳过。Word 等格式会列为暂不支持，需要先转换为 Markdown。图片、PDF、音视频作为文内附件导入。

## 使用

1. 勾选文档，支持全选。点击文件名称编辑该篇设置。
2. 新文档默认 **按源目录归档**：以文档库为根目录，保留全部文件夹层级。例如 `数学/代数/教材笔记/抽象代数/群同态的几个定理.md` 会自动归到 `数学 → 代数 → 教材笔记 → 抽象代数`。不会公开盘符、用户名或本机绝对路径。库根目录下的文档归入“未分类”。也可切换到 **手动选择归档**，选择已有归档或创建归档。手动模式下，归档名称填写最末一级，“父级路径”从顶层依次填写，用 `/` 分隔，例如父级路径 `数学 / 代数 / 教材笔记`、归档名称 `抽象代数`，会创建四级归档；留空父级路径则创建顶层归档。界面实时显示完整归档。应用到全部已选文档时，目录模式下每篇仍按各自路径归档。已发布文档保留原设置，需要时可切换到目录模式。
3. 选择 **自动补全** 或 **自己填写**。自动模式保留已有字段，缺失时用一级标题或文件名作标题，用北京时间的当天作发布日期，正文前 140 字作摘要。开头的 Obsidian 标签行（如 `#math #抽象代数`）会在缺少 tags 时识别为标签，原有 tags 字段优先。发布副本自动移除这些标签行，标签统一显示在文章标题下方，原始笔记不改写。手动模式编辑 YAML，无需首尾 `---`。日期请勿加引号。归档字段以表单为准。
4. 点击 **预览所选文章**，核对正文、字段、引用和附件。
5. 点击 **检查发布**。程序获取 `origin/main`，在独立预览目录中检查类型、构建网站，并核对生成的双链页面与锚点。
6. 检查通过后，勾选公开发布确认，再点 **确认发布**。程序仅提交本次文章和附件，推送到 `main`，由 GitHub Actions 部署。界面显示“已推送”时，部署可能仍在进行，点击“部署记录”查看结果。

原文始终保留。再次提交同一源文件会更新原文章。移动目录或重命名源文件后，只要旧路径已不存在、文件名或原标题唯一匹配历史记录，就会沿用原文章地址和发布日期；列表会提示“路径已变更，将更新原文章”。多个历史记录匹配时会阻止提交，避免误覆盖。旧路径仍存在的同名文档保持独立。预览会列出每篇文档是新建还是更新及其目标路径。网站内容完全相同时不会生成重复提交。程序不会自动删除已发布文章或旧附件。

## 目录归档

完整层级存入 `categoryPath` 列表，`category` 和 `parentCategory` 同步保存最末两级以兼容旧功能。网站分类树、分类导航、文章面包屑和归档筛选均支持完整层级。顶部分类栏只列顶层分类，点击箭头展开下级目录；数学分析与代数都位于数学下面。每个目录可查看全部下级文章；不同父目录下同名的子目录分别统计。旧文章仅有 `category` / `parentCategory` 也继续正常显示。

目录移动后，重新扫描并发布会更新归档，同时沿用原文章地址和发布日期。不会迁移其他未选择的文章。

## 数学文本与分段

- 仅当最终 frontmatter 的 `tags` 列表包含 `Math` 时才转换句号，大小写兼容 `math`。例如 `tags: [Math, 学习]`。文件名、目录、标题、归档及旧版本的手动文本类型都不会触发转换；`mathematics` 等其他标签也不会触发。
- 带有 Math 标签的文章，标题、摘要与正文中的中文句号 `。` 转成英文句点 `.`。链接地址、引用目标和 HTML 属性保持有效，指向这些文章标题的引用会同步转换。未带该标签的文章保留中文句号。
- 保留原文空行：**两段文字之间空一行，发布后就是两个独立段落**。只含全角空格等不可见空白的行也作为空行；代码块和独立公式内部不清理空白。不会把每个普通换行擅自扩展成新段落。
- 提交预览显示转换后的内容和段落间距。原始文件不会被改写。
- 普通公式块若误用 `> $$` 结束，会在发布副本中去掉多余的引用符，避免后续整节文字被吞进公式；正常引用块中的公式保持原样。

## 引用关系

- 支持 `[[文章]]`、`[[文件夹/文章|显示文字]]`、`[[文章#标题]]`、`[[文章#^块ID]]`，以及指向 `.md`、`.mdx`、`.txt` 的普通 Markdown 链接。
- 文内链接会转换为网站现有插件识别的双链，使用稳定目标名定位，因此分类更改不影响链接，网站底部的出链和反向链接仍能收录。
- 缺失、重名、尚未导入的目标会阻止提交并列出原因。重名时写完整路径；首次提交时，一起勾选被引用文档。公开文章不能引用草稿。
- 引用式 Markdown 的 `[文字][ref]`、`![图片][ref]` 支持显式引用标签。普通外链保持原样。
- `![[图片.png]]` 与 Markdown 图片、附件会复制到 `public/images/blog-import/`，文件内容决定附件名。代码块与行内代码里的链接示例保持原样。
- 段落末尾的 `^块ID` 转换为 HTML 锚点。首次创建块锚点时需一起导入目标文档。
- `![[另一篇笔记]]` 的全文嵌入目前会明确报错，请改为普通双链。Markdown 中直接写 HTML/JSX 的本地资源路径需先改为 Markdown 附件语法。
- 标题引用会在实际网站构建后验证；不存在的标题或与网站规则不兼容的锚点会阻止发布。自定义 `permalink` 与当前双链规则不兼容时，也会在构建检查中报错。

## 本地记录和恢复

本地状态、日志、待发布预览在 `.blog-manager/`，已从 Git 排除。保留 `state.json` 可识别重复提交并检测网站文章是否被其他方式修改。不要把预览目录当作正式文章目录。

发布失败时不会显示为已部署，也不会强制推送。网络恢复后重新“检查发布”；如果远程网站有新提交，重新检查会基于最新版本构建。意外关闭发生在推送之后时，下次检查会尝试恢复提交记录。构建失败会保留日志，删除对应预览工作树。

程序仅监听 `127.0.0.1`，校验本地请求来源及会话令牌。GitHub 凭据使用电脑上已有的 Git 登录。首次使用需已有 Node.js、pnpm、Git 及仓库依赖（`pnpm install --frozen-lockfile`）。

如果 Git 配置中的本机代理端口不可用，管理器会在本次请求中尝试直连，不更改全局代理设置。

关闭服务：在 PowerShell 运行 `Stop-Process -Id (Get-Content 'D:\Blog\Mizuki\.blog-manager\server.pid')`，先确认 PID 仍为管理器的 Node 进程且没有发布任务运行。通过命令行启动时按 Ctrl+C 即可。

开发验证：`pnpm blog:manager:test`。端口可通过 `BLOG_MANAGER_PORT` 修改，源目录可通过 `BLOG_MANAGER_SOURCE` 修改；需要自定义 pnpm 入口时使用 `BLOG_MANAGER_PNPM`。双击启动器固定使用默认端口。

YAML 处理使用 [yaml 官方库](https://eemeli.org/yaml/)，最终字段约束以 `src/content.config.ts` 为准。
